# Lesson 4.01 — Prompts Are Programs

## The Big Idea

You already know that code tells a computer exactly what to do.

A prompt does the same thing — for AI.

A bad prompt is like buggy code. A well-built prompt is like a clean, working program. The AI follows your instructions. If your instructions are vague, the output is vague.

---

## Do This First

Take any prompt you've written before. Something simple like:

> "Write me a Python function."

Run it. Look at what you get.

Now rewrite it using this structure:

1. **Role** — Who is the AI?
2. **Goal** — What exactly should it produce?
3. **Format** — How should the output look?

Like this:

> "You are a Python tutor for beginners. Write a function that checks if a number is even or odd. Use simple variable names and add a comment explaining each line."

Run that version. Compare the two outputs.

---

## What Just Happened

The second prompt has three parts:

- **Role:** "You are a Python tutor for beginners."
- **Goal:** "Write a function that checks if a number is even or odd."
- **Format:** "Simple variable names, add a comment explaining each line."

Each part gives the AI more control. The AI didn't get smarter — you got better at giving instructions.

---

## Why This Matters

Think about Minecraft commands. `/give @p diamond 1` is specific. It works. `/give me stuff` does nothing.

Prompts work the same way. The more precise your instruction, the more predictable the result.

---

## The Formula

```
Role + Goal + Format = A prompt that actually works
```

You don't always need all three. But when your output is wrong or messy, check: which one is missing?

---

## Key Takeaway

A prompt is a program. Treat it like one. Write it carefully, test it, and improve it when it breaks.

Next lesson, you'll learn how changing the "Role" part alone can completely transform what the AI gives you.
