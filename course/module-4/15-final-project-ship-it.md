# Lesson 4.15 — Final Project: Ship It

## The Big Idea

"Shipping" means putting your app somewhere real people can actually use it.

Not on your laptop. Not in a preview window. On the internet, with a real URL that someone can open on their phone.

This is the step most beginners skip. They build something cool and it lives forever on their computer where nobody sees it.

You're not doing that. Today you ship.

---

## Do This First

Pick one deployment option and follow through until you have a live URL:

**Option A — Vercel (recommended for web apps)**
1. Go to vercel.com and sign up with GitHub
2. Push your code to a GitHub repository
3. Connect the repo to Vercel
4. Click Deploy
5. Get your URL

**Option B — Replit (easiest if you built on Replit)**
1. Make sure your project is public
2. Click "Deploy" in the top right
3. Get your URL

**Option C — GitHub Pages (for simple HTML/CSS/JS projects)**
1. Push your code to GitHub
2. Go to Settings > Pages
3. Set source to your main branch
4. Get your URL

Once you have a live URL — share it with at least one person.

---

## Pushing to GitHub (If You Haven't Already)

If your code isn't on GitHub yet, this is the moment.

In your terminal or Replit shell:

```bash
git init
git add .
git commit -m "first working version"
```

Then create a new repository on github.com and follow the instructions to push.

If you're not sure how, ask the AI:

> "I have a local project folder. Walk me through creating a GitHub repo and pushing my code for the first time. I'm a beginner."

## Why Shipping Matters

Here's the thing about shipping: feedback from real users is worth a hundred times more than feedback from yourself.

When you use your own app, you know all the quirks. You click around them automatically. A real user has no idea — they'll click exactly where you didn't expect and find every broken thing.

That feedback is how apps get actually good.

Also: you made something real. That's something most people never do.

---

## What to Tell People When You Share It

Don't just send the link. Tell them:

- What it does in one sentence
- What you want them to try
- What to tell you if something breaks

People are more likely to actually test it if you give them a specific thing to do.

---

## What "Done" Actually Means

Your project is done when:

- It's live on a real URL
- The main feature works
- You've shared it with at least one person
- You've written down one thing you'd change if you built v2

That last one matters. The best builders always finish with a list of what's next — not because they failed, but because now they know enough to build something better.
