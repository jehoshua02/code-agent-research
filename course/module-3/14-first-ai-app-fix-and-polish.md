# Lesson 3.14 — Your First AI-Built App (Part 3: Fix and Polish)

## What You'll Learn

No app works perfectly on the first try. Not apps made by beginners. Not apps made by professionals. The job is always: run it, see what's wrong, fix it, repeat.

This process is called iteration. It's not a sign you failed — it's how software actually gets built.

---

## Do This First

Run your app. Use it like a real user would. Try to break it.

Ask yourself:

- Does it do what I described in my plan?
- Is there anything confusing or annoying about using it?
- Does it crash if I type something unexpected?

Find one thing that's broken or missing. Just one.

---

## Then Ask AI to Fix It

Describe the problem to AI as clearly as you can. Here's a good template:

```
My app does [X], but when I [Y], it [Z].

Here's my code:
[paste code]

Can you fix it?
```

The more specific you are, the better the fix will be.

Example of a bad description: "It doesn't work."
Example of a good description: "When I type letters instead of a number, the app crashes with a ValueError."

---

## Repeat Until It's Good Enough

Don't aim for perfect. Aim for done.

A good rule: fix the three most obvious problems, and stop. Chasing perfection on a first project is how projects never get finished.

---

## Optional Polishing Ideas

If your app runs cleanly, here are some small things you could improve:

- Add a friendly message at the start that explains what the app does.
- Add input validation — if the user types something wrong, tell them instead of crashing.
- Format the output so it's easier to read.

Pick one, ask AI to help you add it.

---

## What "Done" Looks Like

Your app should:
1. Run without crashing on normal inputs.
2. Do what you described in your plan.
3. Show output that makes sense.

If it does those three things, it's done. Nice work.

---

## What's Next

Now that your app works, you'll save it to GitHub — so it's permanent, shareable, and safe no matter what happens to your computer.
