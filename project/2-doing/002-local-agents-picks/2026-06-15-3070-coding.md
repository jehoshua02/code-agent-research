## Recommendation

| Layer | Pick | Why |
|---|---|---|
| **Model** | Qwen2.5-Coder-7B (Q4_K_M, ~5 GB) | Apache 2.0; agentic-coding-trained; SWE-bench competitive in size class; fits 3070 with KV-cache headroom |
| **Runtime** | Ollama | MIT; easiest local serving (`ollama pull qwen2.5-coder:7b` → OpenAI-compat API on `localhost:11434`); vLLM is overkill for single-user |
| **Application** | OpenCode | MIT; CLI/TUI; native MCP; provider-agnostic (talks to Ollama via OpenAI-compat); the cleanest "agentic coding from terminal" fit |
| **MCP servers** | filesystem, shell, git-github, code-execution | The core four for coding. Filesystem + shell + git are Anthropic reference impls; code-execution = E2B or Pyodide |
| **Frameworks** | _skip_ | Frameworks are for **building** an agent. OpenCode is a finished application — no framework needed |
| **Techniques** | ReAct, tool use (implicit) | Implemented inside OpenCode's loop; reader doesn't pick |

**VRAM budget:** ~6 GB used (Qwen2.5-Coder-7B Q4_K_M + ~1 GB KV cache at 8K context). Headroom for occasional small concurrent inferences.

## Tradeoffs / alternatives

| Alternative | Why consider it | Why not |
|---|---|---|
| **Aider** instead of OpenCode | Strongest SWE-bench Lite SOTA (26.3%); git-native pair programming | No MCP — fails the hard requirement |
| **OpenHands** instead of OpenCode | SWE-bench Verified leader at 66.4%; native MCP; sandboxed Docker runtime | Heavier (Docker + web UI); slower iteration loop |
| **Goose** instead of OpenCode | 70+ MCP extensions out of the box; Block / Linux Foundation neutral governance | General agent — not coding-specialized |
| **Qwen3-Coder** when released | "Thinking mode" toggle for hard problems | Not yet shipped at time of pick |
| **vLLM** instead of Ollama | OpenAI-compatible API with PagedAttention; production-throughput | Overkill for one user; Linux-only; harder install |
| Bump to **12GB+ VRAM** | Lets you run Qwen2.5-Coder-14B or DeepSeek-Coder-V2-Lite (much stronger) | Capital cost; sub-goal of the project is staying within current hardware |

## Open risks

- **8 GB is tight.** Qwen2.5-Coder-7B at Q4_K_M uses ~5 GB; KV cache for 8K context fills the rest. For 32K+ context (e.g., reading a whole codebase) you'll likely hit OOM. Mitigations: smaller model (Qwen2.5-Coder-3B), partial offload to system RAM (Ollama supports this; slower), or upgrade.
- **MCP-required eliminates Aider**, which is the strongest agentic-coding pick on benchmarks. If MCP turns out to matter less in practice than expected, revisit and consider Aider.
- **No benchmark harness yet.** Survey deliverable 3 (harness) was deferred. SWE-bench Lite locally with programmatic grading is the natural test bed; can be set up in a follow-up.
