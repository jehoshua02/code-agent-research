# Reflection

_Last verified: 2026-06-14_

## 1. What It Is

Reflection (Reflexion) has a model evaluate its own output via verbal feedback, store a self-critique in memory, and use it on the next attempt. Introduced by Shinn et al. (2023). Improves performance across coding and reasoning tasks without weight updates, by reusing structured failure analysis.

## 2. Problem It Solves

LLMs produce errors silently. In a standard generate-and-return pipeline, the model has no feedback loop: a wrong answer is returned as confidently as a correct one, and the same mistake will recur on the next attempt because nothing has been learned from the failure. Without reflection, an agent cannot improve within a single session.

## 3. How It Works

After an initial response is generated, a critique step evaluates it against specified criteria (correctness, completeness, format, test results). The critique is either generated by the same model given a self-critique prompt, or by a separate critic model. The original response and the critique are then fed back into the model to generate a revised response. In the Reflexion framework (Shinn et al. 2023), verbal feedback is stored in an episodic memory buffer and prepended to subsequent attempts, enabling improvement across trials within the same session.

```
response = llm(task_prompt)
for attempt in range(max_retries):
    critique = critic_llm(response, criteria)
    if passes(critique):
        break
    response = llm(task_prompt + response + critique)
return response
```

## 4. When To Use

Reflection is valuable for code generation (where test-case failures provide clear critique signals), long-form writing (where quality criteria are explicit), and agentic tasks with verifiable success conditions. It is most effective when the critique signal is concrete and the model is capable of acting on it.

## 5. When Not To Use

Avoid reflection on latency-critical paths — each reflection iteration adds at least one full LLM round-trip. It is counterproductive when the critique model is not meaningfully better than the generator (self-critique on simple tasks can rubber-stamp bad output). It also adds cost proportional to the number of iterations.

## 6. Implementations

- **Reflexion** — shinn et al. reference implementation; episodic memory + verbal reinforcement loop
- **LangChain** — `LLMCheckerChain` and self-critique chain patterns
- **DSPy** — `Assert` and `Suggest` decorators enforce constraints and trigger revision on failure
- **Guardrails AI** — validator framework that triggers regeneration when output fails schema or semantic checks
